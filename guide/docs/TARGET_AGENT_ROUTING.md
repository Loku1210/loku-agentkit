# 目标 Agent 选择

## 先确认目标工具

简单、无文件操作且不依赖特定工具的任务可以给通用 Prompt。出现以下任一情况时，生成 Prompt 前必须确认目标是 Claude Code、Codex、AGY 或其他 Agent：

- 多 Agent 或子 Agent；
- 文件读取、修改或批量生成；
- shell、浏览器、MCP、插件或其他工具调用；
- 权限申请、删除、commit、push、发布或外部通信；
- 需要使用某个平台特有的回报格式或工作流。

## 推荐分工

| 目标 | 优先适用 | 不宜默认承担 |
|---|---|---|
| Claude Code | 复杂代码库、长任务、架构判断、Claude 专属工具与子 Agent | 未说明目标环境时的工具特定 Prompt |
| Codex | 代码实施、严谨诊断、文件级修改、测试与审查、可控多 Agent | 未授权的外部写入或高成本 Graph |
| AGY | 规则明确、重复度高、工作量大、结果可机械验证、失败可回滚的执行 | 模糊需求、关键架构、科研解释、高风险修改、最终验收 |
| 通用 Prompt | 解释、整理、低风险写作和工具无关任务 | 文件、权限、工具或多 Agent 任务 |

实际选择还应结合当时模型能力、可用工具、配额和目标项目规则；不要把历史印象当作永久能力事实。

## AGY 使用原则

AGY 的优势是使用额度较充足，适合低歧义的大批量工作；主要风险是跳步、缩减范围、用自我声明代替证据，以及在长任务后段降低执行完整性。

只把满足以下条件的任务优先交给 AGY：

- 输入、输出和禁止范围可以明确列举；
- 工作可拆为相对独立的小块；
- 每块都有确定性检查或清晰清单；
- 错误不会直接造成不可逆损失；
- 最终结果可由 Claude Code、Codex、代码检查器或用户复核。

不要让 AGY 独立作最终决定：

- 科研结论、机制解释或因果措辞；
- 安全、权限、删除、发布、交易等高风险操作；
- 跨模块架构设计和含糊需求补全；
- “是否全部正确”的最终验收。

## AGY 分块协议

AGY Prompt 应强制采用以下顺序：

```text
0. 读取规则与输入，输出完整任务清单和分块计划
1. 只执行 Block 1
2. 运行该 Block 的确定性检查
3. 对照清单逐项复核，并保存检查点/证据
4. 仅在全部通过后进入下一个 Block
5. 任一检查失败则局部修正；达到重试上限后停止并报告
6. 完成全部 Block 后输出产物清单、检查证据和未决项
7. 交由 Claude Code/Codex 做独立终审
```

每个 Block 必须定义：

- 输入和允许修改范围；
- 明确产物；
- 不得省略的步骤；
- 可运行的检查命令或逐项验收清单；
- 最大重试次数；
- 通过后写入的进度记录。

“我已检查”“应该正确”不算证据。若无法运行检查，必须列出未验证项，不能自行标记完成。

## 混合工作流

推荐的节省 Token 结构：

```text
GUIDE：澄清目标并设计任务
  ↓
Claude Code/Codex：制定边界、样例和验收标准
  ↓
AGY：按 Block 执行大批量低歧义工作
  ↓
确定性检查：逐块 gate
  ↓
Claude Code/Codex：独立抽查或全量终审
  ↓
失败部分定向返工，而非全部重跑
```

低风险且检查覆盖充分时可以抽查；科研、高风险或检查覆盖不足时应全量审查。
