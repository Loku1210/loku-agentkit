# 记忆治理协议

## 目标

记忆用于减少重复沟通和提高同类任务质量，不用于无限积累对话历史。保存的是可复用规则，不是原始聊天记录。

## 记忆分层

| 逻辑文件 | 内容 | 示例 |
|---|---|---|
| `<MEMORY_STORE>/PROFILE.md` | 经确认的稳定背景 | 长期职责、常用领域 |
| `<MEMORY_STORE>/PREFERENCES.md` | 跨任务表达和质量偏好 | 默认语言、输出结构 |
| `<MEMORY_STORE>/WORKFLOWS.md` | 已确认且重复使用的工作流 | 审查流程、Prompt 生成 |
| `<MEMORY_STORE>/LEARNINGS.md` | 从具体反馈提炼的可复用经验 | 某类交付物必须附自检 |

核心行为规则写入项目指定的唯一规则文件。不要在多个文件复制同一条规则；其他文件只引用它。

## 写入级别

### A：可自动写入

同时满足以下条件时可以自动写入，并在当次回复告知：

- 用户明确表达“以后”“默认”“同类任务”；
- 内容低风险且不涉及权限扩大；
- 与现有规则不冲突；
- 能用一句可执行规则表达；
- 有明显重复使用价值。

典型内容：输出结构、措辞偏好、低风险工具习惯、交付文件命名偏好。

### B：必须先确认

- 身份与长期研究方向的变更；
- 高风险判断标准或受监管领域边界；
- 删除、发布、外部通信或写权限；
- 全局适用或跨项目强制规则；
- 与现有记忆冲突；
- Agent 从间接行为推断出的偏好；
- 需要改写唯一规则文件的硬规则。

确认时给出：拟写入内容、目标文件、适用范围、将替代的旧规则。

### C：禁止写入

- 密码、令牌、密钥、付款或个人敏感信息；
- 未经证实的身份、偏好或科研事实；
- 仅对单次任务有用的临时路径和中间状态；
- Agent 的隐藏推理或大段原始聊天；
- 用户明确要求不保存的内容。

## 标准记忆条目

```markdown
### [简短标题]

- 规则：可直接执行的一句话
- 范围：全局 / 科研 / 编程 / 指定项目
- 来源：用户明确反馈，YYYY-MM-DD
- 置信度：已确认 / 明确低风险
- 复核：触发复核的条件，或“无”
```

## 反馈处理流程

1. 区分“本次修正”与“长期偏好”。
2. 把反馈压缩成单一、可执行、可测试的规则。
3. 检查与唯一规则文件和现有记忆是否冲突。
4. 按 A/B/C 决定自动写入、请求确认或拒绝保存。
5. 写入最具体的逻辑文件，并更新项目的变更记录。
6. 在交付中说明“记住了什么、写在哪里、适用范围”。

## 冲突与衰减

- 当前明确要求优先，但一次例外不自动成为长期规则。
- 新规则不直接删除旧规则；先确认是替代、缩小范围还是例外。
- 同一偏好若多次被用户纠正，以最近一次明确确认的版本为准。
- 发现过时、重复或长期未使用的经验时，提出清理建议，不静默删除。
- 每 3 个月或累计 10 条新学习后，建议做一次记忆审计：去重、检查冲突、确认仍有效。

## 记忆质量检查

每条长期记忆应回答：

- 它会改变未来 Agent 的哪个具体行为？
- 适用于哪些任务，不适用于哪些任务？
- 来源是用户明确表达还是 Agent 推断？
- 如果记错，用户能否容易定位、纠正和删除？

无法回答时不应写入。
