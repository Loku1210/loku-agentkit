# Agent 架构路由

## 核心模型

```text
Direct
  ↓ 需要执行—反馈—修正
Single-Agent Loop
  ↓ 步骤可预定义且需要门槛
Deterministic Workflow
  ↓ 单上下文成为瓶颈或需要职责隔离
Minimal Graph
```

Graph 是多个节点及其数据流、检查点和停止条件；节点可以是 Agent Loop，也可以是代码、测试器、路由器或人工确认。Graph 的价值来自职责与状态转移的确定性，而非 Agent 数量。

## 两层判断

不要把“GUIDE 如何设计 Prompt”和“目标项目如何执行 Prompt”混为一谈：

- **设计层**：判断 GUIDE 是否需要多个 Agent 分别做需求分析、方案设计和独立审查。默认单 Agent；只有方案本身复杂到单一设计者容易遗漏时才升级。
- **执行层**：判断交给目标项目的 Prompt 应要求 Direct、Loop、Workflow 或 Graph。

设计层即使使用 Graph，也只产出方案和 Prompt，不执行目标项目任务。

## 默认路由

| 形态 | 适用信号 | 默认验证 |
|---|---|---|
| Direct | 一次解释、短 Prompt、低风险小改动 | 约束核对 |
| Loop | 单一目标、上下文集中、可反复测试 | Agent 执行 → 测试 → 修正 |
| Workflow | 子步骤固定、门槛可编码、顺序明确 | 每步确定性 gate |
| Graph | 独立子任务、上下文需要隔离、并行收益或独立审查明显 | 节点契约 + join gate + 最终验证 |

## Graph 升级判据

以下 6 项中通常至少满足 3 项，且没有明显反对条件，才建议在相应层使用 Graph：

1. 可拆成至少两个边界清晰、产出契约明确的子任务；
2. 子任务需要显著不同的专业视角或工具；
3. 单 Agent 上下文预计过长，容易发生指令干扰或上下文腐烂；
4. 子任务可安全并行，并行能显著降低耗时；
5. 结果属于高风险产出，需要独立 maker–checker 分离；
6. 失败可以局部隔离和重试，不必重跑整个任务。

## 不升级 Graph 的信号

- 一个 Agent 在一个清晰 Loop 中即可完成并验证；
- 子任务高度耦合，拆分后需要频繁同步；
- 输入很小、交付物单一；
- 多 Agent 只会重复阅读相同上下文；
- 没有明确的节点输出格式、合并规则或现实验收标准；
- Token、时间或并发预算不足。

## 成本分级

- **S0 Direct**：单 Agent，一次或少量调用。
- **S1 Loop**：单 Agent，多步执行与自检；默认选择。
- **S2 Minimal Graph**：协调者 + 1 个专职执行/审查节点，或 2 个独立节点；需说明收益。
- **S3 Full Graph**：3 个以上专业节点、并行分支或多轮交叉审查；仅用于复杂、高价值任务，并先获得用户明确授权。

若平台政策要求，多 Agent 均须显式授权。不能因用户说“尽量做好”就自动推断无限 Token 预算。

## 最小 Graph 设计卡

启动前应能用一张小图或以下六项说清：

1. **节点**：每个节点只负责什么；
2. **输入契约**：它能看到哪些必要信息；
3. **输出契约**：文件、结构或判断格式；
4. **边与 gate**：何时流向下一节点，谁可拒绝；
5. **停止条件**：成功、预算、超时、不可恢复错误或人工升级；
6. **现实锚点**：最终由什么外部证据证明完成。

推荐的高价值最小结构：

```text
Planner/Router
   ├── Maker
   └── Independent Checker
             ↓
      Deterministic Gate
             ↓
     Accept / Targeted Retry
```

独立审查者应获得必要产物与验收标准，而不是完整继承 maker 的推理历史，以减少锚定和上下文污染。

## 防止常见失败

- **上下文腐烂**：只传递结构化交接物，不转发全部对话；长任务阶段性压缩。
- **错误级联**：在高影响边设置 gate；失败局部回退，不默认继续传播。
- **工具过载**：每个节点只获得完成职责所需工具；避免多个节点同时改同一文件。
- **协调税**：能串行就不盲目并行；合并前明确唯一负责人。
- **自我确认偏差**：关键结论由独立 checker 或确定性检查器验证。
- **无限循环**：预设最大重试次数与升级条件。

## 路由输出格式

复杂任务开始前，用一句话说明：

```text
架构：S1 单 Agent Loop。
原因：目标集中且可用测试闭环验证，多 Agent 的隔离收益不足以覆盖成本。
```

若建议 Graph，则补充节点、并行关系、预计成本等级和需用户确认的权限。
