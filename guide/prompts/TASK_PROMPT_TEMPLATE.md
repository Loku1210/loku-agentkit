# 通用任务 Prompt 模板

按目标工具删减无关字段。方括号内容必须替换，不能把占位符原样交给执行 Agent。

生成前先标记目标：`通用 / Claude Code / Codex / AGY / 其他`。涉及文件、权限、工具或多 Agent 时不得省略。

```markdown
# 角色

你是[具体角色/专业能力]，负责在[工具或项目环境]中完成本任务。

# 最终目标

[一句话描述必须实现的可观察结果]

# 背景

- 用户目的：[为什么做]
- 当前状态：[已经具备什么]
- 相关上下文：[只提供完成任务所需信息]

# 输入

- 文件/目录：[绝对路径或明确来源]
- 数据/材料：[内容及格式]
- 已知限制：[环境、依赖、时间、Token 等]

# 允许与禁止

允许：
- [可读取、修改或调用的范围]

禁止：
- [原始数据、范围外文件、外部发布、commit/push 等]

如需要超出上述权限，先停止并说明原因，不要自行扩大范围。

# 执行要求

1. [必要的检查或准备]
2. [核心执行步骤或决策规则]
3. [验证与修正]

任务理解低于 95%、存在会显著改变结果的歧义或缺少关键输入时，先一次提出 1–3 个问题，并说明默认假设。

# 架构与成本

- 目标 Agent：[通用 / Claude Code / Codex / AGY / 其他]
- 默认使用：[Direct / 单 Agent Loop / Workflow]
- 只有满足[明确升级条件]时才建议 Graph。
- 多 Agent 前：[是否需说明节点、成本并取得授权]

若目标是 AGY，还必须补充：

- 完整 Block 清单及顺序；
- 每个 Block 的输入、产物、禁止范围和 gate；
- 未通过不得进入下一 Block；
- 进度与检查证据的保存位置；
- 最终由 Claude Code/Codex/用户进行独立验收。

# 交付物

- [文件/报告/代码/Prompt]
- 保存位置：[绝对路径或命名规则]
- 输出格式：[结构、语言、篇幅]

正式科研、写作或多文件任务还应明确：

- Claim–Evidence Ledger：[目标项目保存路径 / not-applicable 及理由]
- Asset Manifest：[目标项目保存路径 / not-applicable 及理由]
- Final Package Gate：[目标项目保存路径 / not-applicable 及理由]
- 字段与状态遵循目标项目的记录协议；目标项目若有更严格协议，从其规定。

# 验收标准

- [可机械检查的条件]
- [内容或质量条件]
- 现实锚点：[测试命令、可打开文件、数据对照、权威来源或外部状态]

# 失败与异常处理

- 测试失败时：[返回哪个步骤、最大重试次数]
- 新旧结果不一致时：[如何报告]
- 无法完成时：[需保留哪些证据、向用户请求什么]

# 最终回报

简洁报告：
- Outcome
- Files changed / Deliverables
- Verification performed
- Assumptions
- Risks or remaining decisions
```

## Prompt 自检

- 是否写的是可观察结果，而非模糊的“做好/优化”？
- 输入和权限是否具体到路径或系统？
- 是否删除了无关背景和重复规则？
- 是否定义了停止条件与验收证据？
- 实质性 Claim 是否映射到证据、来源路径、强度、局限和允许措辞？
- 多文件交付是否有 Asset Manifest 与 Final Package Gate？
- 是否区分模型判断与确定性检查？
- 是否明确什么情况下提问、重试或升级权限？
- Graph 是否真的比一个清晰 Loop 更有净收益？
